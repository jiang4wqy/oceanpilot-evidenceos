# 当前页面 DeepSeek 接入与本地部署复验

用户发现当前页面对“你是谁”和“目前缺什么”重复返回带有 `ASSESSED` 的状态模板。本轮检查确认：案件 HTTP API 已连接，但用户实际访问的 8026 服务仍是 `OFFLINE_FALLBACK`；之前在另一临时服务上完成的 DeepSeek 验证不能代替这个入口的实际接入。

## 修正内容

- 将本机授权凭据放入被 Git 忽略的 `.env`，通过该配置启动用户实际访问的服务，保留原案件。配置文件权限为 0600，未提交或展示密钥。
- 输入附近显示当前服务配置；当前配置、每条回复的实际来源与历史回复来源分别显示。没有来源的旧聊天条目明确标为未知。
- “分析当前版本”及错误重试发起新的 `USER_MESSAGE` 分析，避免再次回放同版旧离线结果。普通刷新仍只读取已保存结果。
- 离线/异常回复区分助手身份、登记缺口、责任方和人工审核状态；6/6 明确仍需复核且正文未读取，不再直接输出 `ASSESSED` 等内部阶段值。
- 使用 SQLite backup 将既有三个数据库从临时验收目录迁到项目 `work/local-demo`，保留原库；逐库完整性检查与各表行数核对通过，原案件 ID、版本、材料、审核及分析历史保留。

## 实际运行结果

在同一浏览器案件 `19d4cb22-3786-42c1-a029-bbc6f550ac9f` 上操作，案件版本始终为 11，人工审核状态仍为 `UNREVIEWED`。当前服务报告 `DEEPSEEK_LIVE / DEEPSEEK / deepseek-chat`。

| 页面操作 | 实际结果 |
| --- | --- |
| 发送“你是谁” | `MODEL`；介绍 OceanPilot 案件助手及人工复核边界 |
| 发送“目前缺什么，补充后会改变什么？” | `FALLBACK / INVALID_ACTION`；模型返回未通过动作合同，页面如实显示降级 |
| 对上述问题明确重试一次 | `MODEL`；说明 6/6 已登记、无登记缺项，但仍待人工复核、文件正文未读取 |
| 点击“分析当前版本” | 生成新的回合 ID，证明没有回放；本次为 `FALLBACK / UNSUPPORTED_CLAIM`，文本边界检查触发后返回确定性说明 |

四个页面请求的实际来源、回复及版本记录在 [结构化记录](api-integration-live-results.json)。另外执行一次不写案件的最小诊断调用，返回合法 `NONE` 动作、`requires_confirmation=true` 和 `MODEL`。没有用这次独立诊断结果替换页面失败记录，也没有放宽人工确认或文本边界校验。

这些结果证明实际页面已调用 DeepSeek、返回结果能正确区分问题，并且不合规输出会降级；不证明每次请求都能通过模型输出校验或具有真实业务准确性。

迁移后健康检查、商户和业务端角色检查通过，原版本 11 及已保存分析可恢复。密钥与数据库均被 Git 忽略；后端最终发送继续关闭。其他表单长度与弹窗键盘问题未混入本轮接入修复。
