# Oceanpayment Transaction Diagnostic System — 双端 Dashboard 设计

## 1. 产品定位与选择

这不是通用数据看板或聊天机器人，而是支付运营人员的交易诊断工作台。核心链路固定为：

`交易 → 处理路径 → 失败/决策点 → 根因 → 支持证据 → 影响 → 建议动作`

视觉方向对比：

| 方向 | 特征 | 取舍 |
| --- | --- | --- |
| A Payment Network Console | 高密度、强权威、偏网络运营 | 信息效率高，但品牌辨识度弱 |
| B Modern Payment Operations | 清爽、接近 Stripe / Adyen | 易上手，但容易显得通用 |
| C Oceanpayment Intelligence | 保留运营密度，加强 Oceanpayment 海洋绿与证据链 | **采用**；兼顾可信度、品牌感和诊断效率 |

## 2. 信息架构

### 商户客户端（端口 8002）

- 概览：授权表现、失败交易、风险、3DS、拒付率、需要关注事项
- 交易：高密度交易表、状态与时间筛选、导出入口
- 诊断：根因、响应码、失败阶段、路径、证据、影响、建议动作、相似交易、时间线
- 异常与争议：立案、原因确认、缺证补全、证据就绪度、打包、人审、模拟提交
- 风险：交易前风险提示与应留存证据
- 次级入口：规则与配置、审计日志、设置

### 运行维护端（端口 8003）

- 运行总览：服务、数据库、请求量、P95、5xx、关键预警
- API 监控：规范化路由、调用量、4xx/5xx、错误率、平均延迟、P95、最近状态
- 故障预判：以确定性阈值解释风险信号和处置建议
- 业务指标：人工复核、申诉阻断、风险分级等流程压力
- 审计与配置：采集边界、窗口语义、外部连接事实边界

## 3. 主要旅程

### 支付支持 30 秒诊断

1. 使用全局搜索输入 Payment ID、订单号或商户。
2. 打开交易，先看到一句根因结论及失败阶段。
3. 沿处理路径定位停止位置。
4. 分开核对 Observed Facts、System Interpretation、Recommended Action。
5. 检查支持证据与待补字段，再执行下一步。

### 争议补证

1. 选择原因码场景并创建案件。
2. 系统在材料不齐时用黄色高显著区域列出缺失项，并突出下一项。
3. 只有材料收集完成或人工确认不足后，才进入规则评估。
4. 打包与模拟提交保留人工确认和审计。

### 运行维护

1. 先看综合状态与当前严重信号。
2. 下钻到具体 API 的错误率和 P95。
3. 根据阈值证据判断是服务、接口还是业务积压。
4. 按建议动作处理；不使用不可解释的“故障概率”。

## 4. 设计 Token

这些色值是当前原型基于资料与公开视觉观察提取的产品色卡，不声明为 Oceanpayment 官方品牌规范。

```css
--op-primary: #087A70;
--op-primary-hover: #06685F;
--op-teal: #15988A;
--op-soft: #DFF3EF;
--op-deep-ocean: #123B3A;
--op-background: #F5F8F7;
--op-surface: #FFFFFF;
--op-text: #172321;
--op-text-secondary: #63716E;
--op-border: #DDE7E4;
--op-success: #178A52;
--op-warning: #C88722;
--op-critical: #C84646;
--op-info: #3676A8;
```

- 字体：系统无衬线字体栈；ID、响应码和时间使用等宽字体。
- 圆角：主要容器 8–10 px；状态标签 5–6 px。
- 阴影：只用于必要层级，默认依靠 1 px 边框分组。
- 密度：桌面 1440 优先，同时保证 1280/1024 可用。

## 5. 组件与内容规则

- Global Search：顶栏视觉重点，支持 `⌘K` 聚焦和回车定位。
- Status Chip：成功、关注、严重、未调用使用统一语义色。
- Dense Table：交易和 API 均以表格为主，不拆成大卡片。
- Processing Path：以阶段节点显示已通过、失败和未执行。
- Diagnostic Triad：必须分开“观察事实 / 系统解释 / 建议动作”。
- Missing Evidence Alert：材料未齐时置于任务区域顶部，写清数量、缺什么和下一项。
- Failure Signal：标题、证据、建议动作三段式；不得只有颜色或分数。
- Confirmation Gate：会改变案件或模拟提交的动作保留显式人工确认。

## 6. 当前事实边界

- 交易列表与诊断样例是合成数据；已有争议 API 仍驱动真实本地状态机和 SQLite。
- 维护端请求监控是近 15 分钟进程内滚动窗口，不是生产可观测性平台。
- Oceanpayment 真实字段、历史案件、生产 API、银行规则和上游申诉接口尚未接入。
- “故障预判”仅为可解释阈值，不输出模型生成的故障概率。
