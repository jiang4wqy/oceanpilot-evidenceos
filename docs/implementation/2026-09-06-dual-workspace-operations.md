# 双端案件操作说明

本次沿用现有页面、样式和原生 JavaScript，不引入新前端框架。
`/demo` 是商户材料提交区，`/business` 是企业争议运营区。两端共享主服务与案件数据库；
`/admin` 仍为独立的只读运维入口。页头固定显示演示身份，不能作为生产认证方案。

## 演示主线

| 步骤 | 入口与操作 | 应看到的回执或结果 |
| --- | --- | --- |
| 建立副本 | 商户端 → 演示样例 → 新建 A 样例副本 | 后端建立新案件，5/6 材料登记、一个关键缺口；显示案件号与版本 |
| 理解阻断 | 打开案件 → 概况及材料登记，可向 Agent 询问缺什么 | 状态、责任方、为何缺、补后改变；本次说明有实际来源标签 |
| 登记补证 | 缺失项“登记材料” → 选择合成文件名或合成模板 → 明确来源 → 确认登记 | 保存案件、版本、审计与命令编号；只登记元数据，正文未读取 |
| 跨端复核 | 同案右上角切换企业争议运营区 → 复核与结果 | 保留案件号、分区与列表筛选；读取同案当前版本 |
| 记录决定 | 填写意见 → 预览本版本范围 → 确认写入复核决定 | 范围仅材料登记清单与内部处理门槛；回执绑定具体版本 |
| 导出成果 | 生成当前版本摘要 → 下载 HTML / JSON | “案件复核摘要（合成示例）”，冻结版本、已保存记录，导出不再调用模型 |
| 商户查看 | 切回商户端 → 复核与结果 | 同版决定与已保存摘要；不能从商户页面记录业务复核 |
| 展示阻断 | 新建 B 副本，或撤回 A 的某项关键材料 | 关键缺口阻断，旧版复核不再表示当前通过；仍可记录退回/驳回 |
| 跨场景自测 | 新建 C 副本 | Visa 13.1 的对应规则、缺口和解释，不套用 Visa 10.4 |

三个样例均假定已进入正式争议流程，数据与材料全部为合成。
普通支付失败或 3DS 挑战失败不能直接作为拒付；手工建案需要明确勾选正式争议前提。
“新建副本”不会清空数据库，也不在浏览器修改材料就绪度。

## 处理边界与恢复

- 案件列表同时展示名称、阶段、缺失数量、待处理方、当前版复核与真实更新时间。
  单案分区共用一个后端快照，URL 保存 `case`、`section`、`view`、`q`、`status`、`owner`。
  规则详情按精确版本打开，可返回原案；刷新和跨端也保留上下文。
- 已登记材料展示文件名、来源、登记人、登记时间、登记版本；撤回历史可展开。
  文件选择仅访问文件名，不读取正文。清单齐全不表示内容一致、交易真实或胜诉率。
- 来源未知或人工疑点展示原值、建议值与各自来源。来源未明确时，应撤回原材料登记，
  明确来源后重登，再由企业运营方复核疑点；单独记录知悉不能解除阻断。
- 审核先显示本版本的范围预览，再明确确认。确认请求绑定案件版本及规则指纹，后端核对
  两者。切换案件清除原案表单；案件版本或规则依据变化清除旧版待确认预览。已保存历史继续展示，但不会标成当前版本审核结果。
- 操作进行中禁用重复写入；每次命令的编号及原始请求在当前标签会话中保存。
  超时先查询原回执，`UNKNOWN` 不是原请求已停止的证明。重试仍使用同一命令编号与请求，
  新写入在结果明确前被禁用。网络恢复后可查询原回执，无需重复创建案件。
- Agent 展示本次 `MODEL`、`DETERMINISTIC` 或 `FALLBACK` 来源；离线规则模式明确标识。
  模型建议不会直接批准、更改材料或发送案件；旧案件/旧版本的晚响应不会覆盖当前内容。
- 主演示结束在人工登记复核和冻结摘要。新页面没有最终发送接口路径，后端默认关闭发送。
  未实现模块是禁用的“规划中”入口，不增加经营大屏或空白页面。

自动化证据位于 `tests/web/test_page_runtime.py`、`tests/web/test_rendering.py` 与
`tests/api/test_demo_page.py`。实际浏览器/集成结果另记在本轮验收账本中；该说明本身不代表
实时模型、正式卡组织规则或生产身份体系已验收。
