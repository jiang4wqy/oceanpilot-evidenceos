# 技术答辩边界

**这次展示证明什么？**

在明确标注的合成交易上，商户与运营使用独立账号，通过真实应用上传文件、检查字段和案件匹配、修订材料、提交人工审核。演示停止在待审核，不等于赢单、退款、正式提交成功或结案。

**客户实际上传什么？**

2026-09-14 用户提供的沟通截图中，老师反馈材料类型都有可能，截图、PDF 居多，并强调不可篡改的证据文件。这是产品需求输入，不是上传格式规范或授权文件。当前演示只支持 UTF-8 TXT/JSON/单行 CSV 的结构化检查。不能说已经适配真实客户常用材料。应在后续确认实际格式、大小、来源/签名要求、人工审核方式，再规划原件保留与提取/复核路径。

**文件哈希是否等于不可篡改或真实性证明？**

不是。系统实际保存字节、记录 SHA-256、版本及操作者，支持核对保存后的字节是否变化。PDF 扩展名本身不意味着不可修改；哈希不能证明上传前没有修改、谁出具文件、业务事实真实或来源可信。当前没有不可变存储、可信时间戳/签名验证的完整证据链保证。

**“内容足够”是否等于审核通过？**

不是。SUPPORTED 表示当前受支持字段、交易/案件匹配检查通过。必需项和关键项不同：任一必需项缺失仍阻止提交；关键标记只说明重要性。整包审核与批准必须由正常人工流程完成，材料变化使依赖旧版的批准/提案失效。没有 PDF/截图 OCR，没有恶意文件扫描，也不证明真伪。

**OceanPilot 是否正在调用大模型？**

本候选启动时关闭实时模型，采用已有确定性检查/降级机制。实时模型测试因凭据缺失跳过，不算通过；不能把确定性回答包装成实时模型推理。现有上下文授权与来源过滤的自动测试通过，并不等于任意模型的安全性或答案准确率得到认证。

**飞书实际做了什么？**

飞书由 A 负责。本 B 实例不装入飞书配置，未验证真实回执或自动 SLA 外发；A 的 8002 与本 8015 三库不同。预览卡片、Mock 测试、本地 reminder/handoff 均不等于已送达。共同录制前须核对实际环境、授权收件人、角色、当前任务与真实回执，失败不能标 SENT。

**超时/未知结果如何处理？**

保留 UNKNOWN，通过被允许的查询取得真实结果，受控重试复用相关提交标识，不因网络超时重新建成功结果。本轮完整自动集覆盖已有门禁，本轮浏览器未执行上游提交/查询。商户逾期只产生对应运营跟进，不因沉默推定接受责任或正式失权。

**为什么有三个期限？**

分别是商户回应、内部审核/处理、外部响应目标。当前任务根据责任人选择主期限，其他期限可查看说明。此案 72/96/120 小时是合成规则，用来验证工作流，不能宣称是 Visa 官方时限。规则未确认时应显示未确认；结案期限只留作历史。

**数据在哪里，如何恢复？**

现有 SQLite，材料字节存在 BLOB，业务命令保留审计及版本。用停止状态下的 SQLite backup API 复制三库，经完整性/哈希检查恢复到新目录。当前实现是演示规模，不是新建的生产数据库、对象存储或高可用平台。

**可以报告效率提升/胜诉率吗？**

不能从合成演练推出真实商户收益或胜诉率。本轮只有 B 的技术验证；C 的独立三次演练、两位非开发同学可用性观察与有基线的测量还未完成。
