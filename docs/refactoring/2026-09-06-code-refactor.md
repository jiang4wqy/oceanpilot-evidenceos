# 案件工作台代码重构交接

本次只实施代码整理，为后续双端流程优化和 P0 业务修复提供共用模块。
基准为 `master` 的 `62ebfcaeede2841c0b23c9d953e93f6273882b48`，
工作分支为 `refactor/case-workspace-foundation`。

## 基线与范围

- 基线全量测试：`1197 passed, 6 skipped`。
- 六项跳过来自五项可选实时模型测试与一项 PowerShell 环境测试。
- 保留 FastAPI、现有 HTML/JavaScript、SQLite 数据结构、URL 和公开 DTO。
- 不合并 Foundation 与 Chargeback，不修改历史数据库，不新增框架或运行时依赖。
- 不在本次实现业务审核端、演示 A/B/C 预置、摘要导出、发送开关、正文识别或真实联调。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `api/agent.py` | Agent HTTP 输入、依赖组装、响应校验与状态码 |
| `api/agent_schemas.py` | 现有严格请求/响应合同及持久化序列化边界 |
| `application/case_agent.py` | 建案/分析/回放/保存 Agent turn 与人工确认的编排 |
| `application/agent_views.py` | 不依赖 HTTP 的不可变 Agent 视图、引用和审核提案构造 |
| `application/case_snapshot.py` | 案件纯读取及共用 Delivery 渲染，供案件 API 和运维概览复用 |
| `application/chargeback_supervisor.py` | `snapshot` 确定性投影；`advance` 在明确操作后调用模型解释 |
| `application/chargeback_packager.py` | `preview` 确定性材料包；`build` 保留显式模型说明生成 |
| `web/rendering.py` | 从已打包资源组合完整内联 HTML，不新增静态资源路由 |
| `web/merchant/` | 用户页面外壳、样式、案件状态及各操作模块 |
| `web/operations/` | 原运行维护页面外壳、样式及交互 |
| `web/shared/` | 共用请求期限、在途请求合并及请求先后顺序判断 |

应用层仍只通过应用/领域合同工作，不依赖 FastAPI、SQLite 或具体模型适配器。
界面资源作为 Python package data 发布，不依赖前端构建服务或网络 CDN。

## 读取与操作合同

| 行为 | 本次规则 |
| --- | --- |
| `GET` 案件详情/列表、运维案件概览 | 从已持久化案件投影状态与缺口；不调用模型、不改案件、不新增业务评估计数 |
| `GET` 材料包 | 一次规则匹配生成确定性预览；现有 `cover_note_source` 使用兼容值 `FALLBACK` |
| 建案、原因确认、补证、撤回、收集结束 | 保留现有命令与持久化行为；明确操作后仍可使用模型辅助解释 |
| Agent 分析 | 读取确定性案件后进行明确的 Copilot 调用；自动触发可回放已有同版本结果 |
| Agent turn 保存 | 绑定产生结果的 `delivery.revision`，不另取一个较新版本重新标记旧结论 |
| 人工审核 | 保留既有来源 turn、版本检查、原子持久化和重复确认回放 |
| 页面状态 | 同一选中案件由一个服务端 snapshot 提供；兼容属性不再分别保存副本 |
| 迟到响应 | 核对案件、版本及请求顺序，过期结果不能覆盖当前案件 |
| 请求失败/超时 | 释放前端等待状态；不自动重试写入，也不将客户端去重称为后端业务幂等 |

`CaseSnapshot` 是从单个已载入案件版本生成的不可变读视图，不是已经完成的
导出冻结包。它没有把规则目录、人工审核和历史 Agent 结果放进跨存储事务。
跨版本导出保护、规则版本固定、当前审核/结果快照组合仍属于后续摘要功能。
举证时限是按当前时钟计算的派生值，不因相同案件版本而冻结。

## 有意改变的行为

原先刷新案件列表或运维页面会再次运行 Evidence/Assess 模型；完整案件的刷新还会
增加评估次数。现在刷新只读取确定性状态，模型次数和业务计数保持不变。
材料包 GET 使用确定性说明；显式 `PackagerAgent.build()` 仍可生成模型说明。
此变动不改变材料包含顺序、缺口、就绪计算、人工门槛或规则匹配策略。

## 后续工作边界

现有 Visa 10.4 硬编码、仅凭登记齐全生成“内容一致”的话术，以及 Mock 发送版本机制，
按原计划留到 P0 修复。重构只是把这些逻辑集中到可复用位置，不代表已修复业务口径。
原 `/admin` 仍是运行维护端，尚未重新分配为业务审核端。

后续开发应先在独立改动中修复规则与材料表述，再基于同一案件读模型整理双端流程。
不要让页面、AI、摘要分别实现规则匹配或审核判断。

明确操作仍会调用模型和记录评估。另验证前端过期结果处理、请求释放和已安装 wheel
的页面资源可用性。
