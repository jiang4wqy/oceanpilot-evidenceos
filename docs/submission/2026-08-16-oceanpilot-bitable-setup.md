# OceanPilot 飞书多维表格 AI 协作台配置说明

目标表名：`OceanPilot｜跨境商户成功案件台`

当前案件台：<https://larkcommunity.feishu.cn/wiki/PkLAwdnf4iCDxrkUkIYcHzxGnIb>

数据文件：[oceanpilot-bitable-synthetic-cases.csv](oceanpilot-bitable-synthetic-cases.csv)

## 1. 当前边界

- 表内三条记录全部为 Synthetic 演示案件。
- 当前协作台用于验证 AI 摘要、补问、视图和提醒，不声称已与 OceanPilot API 实时双向同步。
- “举证截止时间”是内部演示准备窗口，不是卡组织官方期限。
- Synthetic 演示时钟固定为 `2026-08-16 20:00`；“是否临期”按距内部准备截止不足 48 小时计算。
- 多维表格不执行支付、退款、风控放行、配置变更或真实申诉。
- 若当前飞书租户不开放 AI 字段或自动化权限，保留主表与视图，并在方案中按实际完成项描述。
- 截至 2026-08-16，3 条 Synthetic 记录、5 个视图、2 个 AI 自动填充字段和 4 组视图筛选已经创建；提醒自动化尚未启用。

## 2. 字段类型

| 字段 | 建议类型 | 说明 |
|---|---|---|
| 案件编号 | 单行文本 | 稳定演示 ID |
| Synthetic标识 | 单选 | 固定为“是” |
| 商户名称 | 单行文本 | 合成名称 |
| 场景类型 | 单选 | 拒付申诉、风控拒绝、配置不匹配 |
| 卡组织 | 单选 | Visa、不适用 |
| Reason Code | 单行文本 | 不适用时保留内部场景码 |
| 当前状态 | 单选 | NEED_EVIDENCE、READY_FOR_REVIEW、APPROVED、CLOSED |
| Evidence Readiness | 百分比 | 材料就绪度，不是胜诉概率 |
| 缺失证据 | 多行文本 | 只记录材料类别，不放证据正文 |
| 当前责任域 | 单选 | DISPUTE_OPS、RISK_OPS、TECH_SUPPORT |
| 当前责任角色 | 人员或单行文本 | 截止前可先使用角色名称 |
| 举证截止时间 | 日期时间 | Synthetic 内部准备时间 |
| 截止依据 | 单行文本 | 明确非官方期限 |
| 是否临期 | 公式或复选框 | 演示可直接导入“是/否” |
| 规则版本ID | 单行文本 | 仅精确映射时填写 |
| 规则核验状态 | 单选 | UNVERIFIED_SUMMARY、不适用 |
| 人工复核原因 | 多行文本 | 说明人工门槛 |
| 人工审批状态 | 单选 | 待补资料、待人工审批、已批准、已关闭 |
| 下一动作 | 多行文本 | 确定性结果或人工建议 |
| Web演示定位 | URL或单行文本 | 本地演示路径不冒充公开站点 |
| 审计摘要 | 多行文本 | 不包含证据正文和敏感数据 |
| 最近更新时间 | 日期时间 | Synthetic 演示时间 |
| AI运营摘要 | AI字段或多行文本 | 由 AI 字段一生成 |
| AI补问与下一动作 | AI字段或多行文本 | 由 AI 字段二生成 |

## 3. AI 字段一：运营摘要

输入字段：场景类型、当前状态、Evidence Readiness、缺失证据、当前责任域、人工复核原因、举证截止时间。

Prompt：

```text
你是跨境支付运营协作助手。只根据当前记录中的结构化字段，生成 80 字以内的中文案件摘要。必须说明当前状态、最关键的证据缺口、责任域和下一动作。不得推测胜诉概率，不得补写记录中不存在的交易、银行或商户事实；若信息不足，明确写“待补充”。
```

## 4. AI 字段二：补问与下一动作

输入字段：缺失证据、当前责任域、Evidence Readiness、举证截止时间、人工复核原因。

Prompt：

```text
根据记录中的缺失证据和责任域，生成一条可直接发送给责任人的中文补问，最多 100 字。先说明需要补充的具体材料，再说明用途和截止要求。不得要求密码、完整卡号、验证码或其他敏感凭据；不得给出胜诉承诺。若 Evidence Readiness 已达标，则输出下一步人工评估或审批建议，不再要求重复补证。
```

## 5. 五个视图

### 全部案件

显示全部字段；默认按“最近更新时间”倒序。

### 待补资料

筛选：`当前状态 = NEED_EVIDENCE`。

重点列：案件编号、商户名称、缺失证据、当前责任角色、举证截止时间、AI补问与下一动作。

### 临期案件

筛选：`是否临期 = 是` 且 `人工审批状态` 不是“已关闭”。

重点列：截止时间、缺失证据、当前责任角色、AI运营摘要。

### 待人工审批

筛选：`当前状态 = READY_FOR_REVIEW` 或 `人工审批状态 = 待人工审批`。

重点列：Evidence Readiness、人工复核原因、规则版本ID、下一动作、AI运营摘要。

### 已完成与复盘

筛选：`当前状态 = CLOSED` 或 `人工审批状态 = 已关闭`。

重点列：场景类型、规则版本ID、审计摘要、最近更新时间。

## 6. 三条自动化

当前状态：以下三条为已完成设计、尚未启用的自动化配置。启用后会向飞书成员发送通知，须由团队确认通知对象与频率后再开启。

### 待补资料提醒

触发：记录进入 `NEED_EVIDENCE`。

动作：向当前责任角色发送案件编号、缺失证据、截止时间和“AI补问与下一动作”。

### 临期提醒

触发：`是否临期 = 是` 且案件未关闭。

动作：通知责任角色和争议运营；明确这是内部准备时间，不描述为官方卡组织期限。

### 人工审批提醒

触发：记录进入 `READY_FOR_REVIEW` 或审批状态变为“待人工审批”。

动作：发送 AI 运营摘要、人工复核原因、规则版本 ID 和 Web 演示定位；不得自动批准或执行上游动作。

## 7. 演示顺序

1. 打开“全部案件”，说明同一协作台可以承载三个支付问题切片。
2. 进入“待补资料”，展示 Visa 10.4 的证据缺口和 AI 补问。
3. 进入“临期案件”，展示责任人和提醒。
4. 进入“待人工审批”，展示配置不匹配案件为何仍需人工确认。
5. 返回 OceanPilot Web 完成规则、Package、人工闸门和 mock 回执，强调专业判断留在内核。
