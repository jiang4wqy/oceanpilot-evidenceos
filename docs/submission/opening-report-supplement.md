> 本文件是两页 PDF 的文字单一事实源。所有已验证能力均使用 synthetic 数据；真实飞书群、公网 HTTPS 回调、Oceanpayment 数据和生产部署尚未验证。

## Page 1｜01 从单点工具到综合商户成功智能体

### 一句话主张

OceanPilot 是证据驱动的综合商户成功智能体：把不同业务问题统一组织为可追溯案件，缺证先补问，过门再判断，责任可交接，高风险动作由人工确认。

### 外部证据

1. **结构化缺口：** Swift 2025 研究显示，跨境支付异常调查消息中，超过 `72%` 的数据字段仍为自由文本。
2. **单点能力已成熟：** Stripe 已按地区、币种和金额动态选择支付方式；Primer 已用事件时间线还原请求与响应。
3. **协作仍需人工还原：** 一位 G2 验证用户指出，历史交易与到账关系仍需人工梳理。这是定性个案，不代表行业比例。

### 商业判断

推荐、时间线和单点 Agent 解决局部效率，却没有自动形成跨角色可交接的证据口径。OceanPilot 因此用“商户成功案件 + 案件证据契约”统一问题描述、证据、判断、责任和审计，再逐步扩展到支付推荐、支付异常、退款、拒付和对账等场景。

### 受控闭环

`问题建案 → 证据补问 → 证据门槛 → 确定性诊断 → 责任路由 → 人工确认`

- AI 处理模糊表达和角色化补问。
- 规则、状态机和证据引用守住确定性。
- 人工确认仅写审计，不等于执行任何业务动作。

## Page 2｜02 两个 synthetic 纵向切片，共用同一证据内核

### 当前已验证

| 纵向切片 | 可演示闭环 |
|---|---|
| 支付异常（8 月 16 日主展示） | 四个 synthetic 场景；公开案件/证据/诊断 API；证据就绪、确定性规则、置信度、责任域、证据与审计引用；signed local Feishu fixture；重复事件与确认幂等 |
| 拒付申诉 | synthetic 建案、原因分类、证据清单、评估、材料包、申诉草稿、人审门、安全扫描、审计与指标 |

### 共用能力与边界

- 当前 OpenAPI 为 `19` 条路径；两个 Web 演示入口分别为 `/demo/payment-incident` 与 `/demo`。
- 本地 signed fixture 经过真实验签和回调路由，但使用进程内 synthetic transport，不连接飞书网络。
- 人工确认只记录审批审计；`no business action`，不执行支付、退款、风控放行、资金移动、生产配置变更或真实拒付提交。
- 真实飞书群与公网 HTTPS 回调尚未验证；真实 Oceanpayment 只读数据、生产鉴权、SLA 运维和业务收益也未验证。

### 阶段路线

1. **当前：** 保持两个可复现的 synthetic 纵向切片与同一案件证据内核。
2. **外部联调：** 在最小权限测试应用中完成真实飞书群和公网 HTTPS smoke，保留时间证据。
3. **只读适配：** 经企业授权后接入 Oceanpayment 订单、3DS、回调、风控、退款和报表查询，不开放资金动作。
4. **试点评估：** 校准规则和角色路由，以企业现有流程为基线测量到证时间、首次路由、改派、人工升级和知识复用。

### 试点目标边界

证据引用率与高风险动作人审率 `100%` 是设计硬约束；资料到齐时间缩短 `30%`、首次责任域命中率 `80%`、改派次数降低 `30%` 均为未来试点目标，不是当前已实现收益。
