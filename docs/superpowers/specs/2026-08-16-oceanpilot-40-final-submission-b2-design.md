## 1. 目标

本轮把现有 OceanPilot 技术原型整理为一份符合 40 强赛官方模板、可由评委快速核验的完整参赛方案，并增加一个独立的飞书多维表格 AI 协作台作为当前飞书 AI 落地能力。

本轮不扩张核心后端范围，不修改现有 Web 演示主界面，不把尚未完成的 Aily、双向同步或真实 Oceanpayment 接入描述为已实现。

最终叙事固定为：

> OceanPilot 是面向跨境 PSP 的证据驱动商户成功智能体。它先把一次支付异常组织为版本化案件，再通过证据契约识别缺口；资料达到门槛后，才由确定性内核形成可引用、可路由、可审核的候选判断。飞书多维表格负责跨团队协作、AI 摘要、补问建议和临期提醒，OceanPilot 内核负责证据、规则、状态和审计，高风险动作由人工确认。

## 2. 官方评分目标

完整方案必须逐项覆盖官方评分表：

1. **AI 应用创新性（30%）**：突出问题切入、证据契约、受控工作流和失败保护。
2. **业务价值（30%）**：展示流程差异、可测量指标和企业试点验证方法，不虚构真实收益。
3. **AI 应用深度（20%）**：展示 AI 进入受理、补问、摘要和材料起草等关键环节，同时由确定性规则和人工约束。
4. **完整度、可落地性与可推广性（20%）**：展示问题、方案、执行、验证、迭代闭环，以及从拒付切片扩展到综合商户成功智能体的路径。

提交文档必须包含官方要求的信息卡和方案成果展示，并建议包含 3–5 分钟 Demo 视频、体验入口、测试说明和自由展示区。

## 4. 完整方案文档结构

正式飞书文档标题格式：

`【40强赛】钱海网络🤝鹿出草莓酱｜OceanPilot：证据驱动的跨境商户成功智能体`

### 4.1 参赛方案信息卡

- 队名：鹿出草莓酱。
- 命题：钱海网络——AI 驱动的跨境商户成功运营助手。
- 一句话摘要：使用本设计第 1 节的短版表达。
- 成员介绍与分工：由用户确认三名成员的真实分工后填写。
- 使用的飞书 AI 能力：多维表格；仅在 B2 协作台实际完成后写成已使用。

### 4.2 命题场景与问题

采用“拒付纵向切片证明综合智能体”的结构：

1. 跨境支付问题跨越商户、PSP、收单行、发卡行和卡组织。
2. 截图、订单、错误码、规则和材料散落在不同系统与聊天中。
3. 普通问答只能解释概念，不能形成可交接、可审计的案件事实。
4. 缺证、误判、反复改派和超期会直接影响处理质量和商户体验。
5. 因此首先打通拒付申诉，再复用相同案件/证据/路由机制扩展到支付失败、退款、对账和配置问题。

### 4.3 三项核心创新

1. **版本化商户成功案件**：上下文、证据、判断、责任和审计围绕同一案件持续演进。
2. **案件证据契约**：约束证据类型、来源、时间、版本和引用；缺证时系统必须补问，不能直接猜测。
3. **AI 提议、规则约束、人工裁定**：AI 处理模糊表达、摘要、补问和起草；确定性内核守住状态、门槛、路由和规则引用；人工批准高风险动作。

创新段必须展示一个安全失败案例：证据不足时，系统返回缺口和下一补问，不输出乐观申诉判断。

### 4.4 完整业务链

主链固定为：

```text
AI 运营总窗口
  → 支付异常
  → 建立 Synthetic 拒付案件
  → 确认 reason code
  → 识别证据缺口
  → 角色化补问
  → Evidence Readiness 达标
  → 确定性评估
  → 精确规则版本引用
  → representment 材料包
  → 人工批准
  → in-process mock connector
  → 回执与审计
```

文档需明确 Evidence Readiness 是材料就绪度，不是预测胜诉概率。

### 4.5 飞书多维表格协作层

OceanPilot Web 保留案件处理和专业判断；多维表格负责跨角色协作与运营视图。当前比赛版使用同一批 Synthetic 案件字段验证协作台，不声称已实时双向同步。

### 4.6 方案价值

同时展示三层价值：

- 商户：一次看清缺什么、为什么需要、下一步由谁处理。
- Oceanpayment 运营：降低反复追问和改派，将专家经验沉淀为可复核流程。
- 企业能力：用同一案件协议扩展到支付失败、退款、对账、配置和商户上线协作。

价值数字必须标记为“试点目标”，不得写成已实现收益。

- 3–5 分钟 Demo 视频完成后补充公开链接。

## 7. B2 多维表格 AI 协作台

### 7.1 边界

- 不修改当前 Web 演示主界面。
- 不把确定性评估或高风险裁定迁入多维表格。
- 不声称已经与 OceanPilot 实时双向同步。
- 使用同一批 Synthetic 案件字段搭建协作层，验证 AI 摘要、补问、提醒和视图流转。
- 如截止前只完成表格而未完成自动化，文档必须按实际完成项降级描述。

### 7.2 主表字段

主表名称：`OceanPilot｜跨境商户成功案件台`

必备字段：

- 案件编号
- Synthetic 标识
- 商户名称（合成）
- 场景类型
- 卡组织
- reason code
- 当前状态
- Evidence Readiness
- 缺失证据
- 当前责任域
- 当前责任人
- 举证截止时间
- 是否临期
- 规则版本 ID
- 规则核验状态
- 人工复核原因
- 人工审批状态
- 下一动作
- Web 案件链接或演示定位说明
- 审计摘要
- 最近更新时间

### 7.3 三个 Synthetic 案件

1. Visa 10.4 非本人交易拒付：主演示案件。
2. 风控拒绝：证明同一案件协议可用于风险协作。
3. 配置不匹配：证明可以推广到支付配置问题。

不得把后两个能力写成与拒付主链相同成熟度；当前 Web 主演示仍聚焦 Visa 10.4。

### 7.4 两个 AI 字段

#### AI 字段一：运营摘要

输入字段：场景类型、状态、readiness、缺失证据、责任域、人工复核原因和截止时间。

提示词：

```text
你是跨境支付运营协作助手。只根据当前记录中的结构化字段，生成 80 字以内的中文案件摘要。必须说明当前状态、最关键的证据缺口、责任域和下一动作。不得推测胜诉概率，不得补写记录中不存在的交易、银行或商户事实；若信息不足，明确写“待补充”。
```

#### AI 字段二：补问与下一动作

输入字段：缺失证据、当前责任域、readiness、截止时间和人工复核原因。

提示词：

```text
根据记录中的缺失证据和责任域，生成一条可直接发送给责任人的中文补问，最多 100 字。先说明需要补充的具体材料，再说明用途和截止要求。不得要求密码、完整卡号、验证码或其他敏感凭据；不得给出胜诉承诺。若 readiness 已达标，则输出下一步人工评估或审批建议，不再要求重复补证。
```

### 7.5 五个视图

1. 全部案件。
2. 待补资料：状态为 `NEED_EVIDENCE`。
3. 临期案件：距离举证截止不足两天且未完成。
4. 待人工审批：证据达标但高风险或低置信度。
5. 已完成与复盘：已产生 mock 回执或关闭。

### 7.6 三个自动化

1. 进入 `NEED_EVIDENCE` 时提醒当前责任人并附 AI 补问。
2. 距离截止时间不足两天且未完成时发送临期提醒。
3. 进入待人工审批时通知审批人，并附运营摘要、规则引用和 Web 案件定位。

自动化只发送协作提醒，不执行支付、退款、风控放行或真实申诉。

## 8. Aily 下一阶段路线

Aily 不作为当前已实现能力，只在落地路线中出现：

```text
用户在飞书描述问题
  → Aily 理解意图与提取安全字段
  → 调用 OceanPilot API 建案
  → OceanPilot 返回证据缺口
  → Aily 角色化补问
  → 证据达标后触发确定性评估
  → 飞书卡片展示依据并请求人工确认
```

Aily 负责语义与交互；OceanPilot 负责证据、规则、状态、幂等和审计；人工负责高风险裁定。
