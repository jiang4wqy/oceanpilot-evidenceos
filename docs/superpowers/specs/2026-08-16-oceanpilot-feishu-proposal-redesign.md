# OceanPilot 40 强飞书参赛方案改写设计

日期：2026-08-16
状态：已获用户批准的文档设计规格
适用范围：飞书云文档、Markdown 源稿、DOCX 交付稿

## 1. 目标与边界

本轮只重写和设计参赛方案，不修改 DeepSeek Provider、Agent API、Demo 页面或其他产品代码。DeepSeek 对接由另一个 Agent 独立完成；文档在收到其可核验提交、测试与真实运行证据前，只使用“计划接入”或“本次展示将演示”的口径。

文档统一定位为：

> **OceanPilot：AI 驱动的跨境支付全生命周期商户成功智能体**<br>
> 从支付问题理解、证据补全、规则判断到人工治理的一体化 Agent 协作平台

拒付申诉是用于验证统一 Agent、案件、证据、规则、路由和审计底座的首条标杆链路，不是项目边界。

本轮非目标：

- 不宣称已经接入 Oceanpayment 生产数据或生产 API；
- 不把 DeepSeek、`POST /api/v1/agent/turns` 或增强执行轨迹写成已验证能力；
- 不虚构客户、收益、业务基线、模型调用记录或成员分工；
- 不将 Evidence Readiness 表述为胜诉概率；
- 不使用生成式图片伪造产品页面、测试记录或真实业务数据。

## 2. 核心设计决策

采用“评分优先的企业方案”结构，并使用三层叙事：

1. **项目愿景：** 面向跨境支付全生命周期建立统一商户成功与支付运营智能体。
2. **本次展示：** 用拒付申诉打通自然语言受理、案件创建、证据补问、规则引用、材料起草、人工确认与审计回放。
3. **后续扩展：** 将同一底座扩展到支付失败、3DS/callback、风控、退款、对账、配置、商户上线和主动风险预警。

正文先回答评委“为什么值得做、AI 深在哪里、现在能验证什么”，再展开技术细节。工程能力必须按“已实现、已验证、本次展示将演示、当前原型、试点目标、路线图”分层陈述。

## 5. 状态词与事实口径

| 状态词 | 使用条件 | 示例 |
|---|---|---|
| 已实现 | 当前代码或页面可以运行 | 版本化案件、证据缺口、规则深链、人工闸门 |
| 已验证 | 有测试、CI 或实际运行结果 | `1148 passed, 2 skipped, 1 warning` 对应固定提交时的记录 |
| 本次展示将演示 | 已进入展示设计，但最终链路或截图尚未冻结 | DeepSeek 自然语言入口、增强 Trace |
| 当前原型 | 可展示，但未接入生产系统 | Synthetic Web、Mock connector、演示规则库 |
| 试点目标 | 需要企业真实基线验证 | 资料到齐时间缩短 30% |
| 路线图 | 尚未实现 | 生产同步、主动预警、多区域规则治理 |

DeepSeek 状态更新规则：

- 只有本地代码或模拟 transport 测试：写“计划接入”或“适配器开发中”；
- 有固定提交、自动化测试和失败降级验证：写“已实现 Provider 适配”；
- 有真实 DeepSeek API 调用、脱敏边界、运行截图和可复现说明：才写“本次展示已接入 DeepSeek”；
- 任何阶段均不得写“已上线生产”。

当前共享工作树中的 DeepSeek 代码尚未提交；定向测试为 4 项通过，但不构成真实在线模型调用验证。文档在工程交接前仍采用“计划接入”口径。

## 6. AI 应用深度章节设计

AI 深度章节必须依次回答五个问题：

1. **AI 做什么：** 理解口语化描述、提取非敏感事实、确认模糊意图、生成角色化补问、解释规则结果、起草摘要和材料。
2. **AI 不做什么：** 不修改证据门槛、不替换规则版本、不预测胜诉率、不跳过人工审批、不执行资金动作。
3. **如何调用：** 以可插拔 `ModelProvider` 接入 DeepSeek、Claude seam、OpenAI-compatible 本地模型和离线 deterministic fallback。
4. **如何编排：** 计划通过 `POST /api/v1/agent/turns` 复用 Intake、Evidence、Assess、Package 等现有能力，不重新实现案件与规则逻辑。
5. **如何证明：** 页面展示 Agent、动作、工具、模型/规则来源、等待状态、降级状态、人工闸门、案件 ID 和规则版本；只展示执行轨迹与依据摘要，不展示隐藏思维链。

章节内使用一张“AI—确定性系统—人工”职责矩阵，以及一张“AI 判断总结”示例卡。示例卡中的事实必须全部来自 Synthetic 案件现有字段，不生成真实商户或支付信息。

## 7. 混合视觉体系

### 7.1 视觉原则

视觉材料分三类，各自承担不同证明责任：

- **AI 生成视觉：** 表达愿景、规模感、业务场景关系和品牌氛围；不得承担工程完成度证明。
- **可编辑信息图：** 表达流程、责任、箭头、对比、状态和评分映射；中文、数字和指向元素均由后期排版生成。
- **真实运行截图：** 证明功能、规则、证据、人工闸门、审计和飞书协作台的实际状态。

所有 AI 生成图内部避免复杂中文。指向箭头、节点名、状态标签和图注必须用 SVG、HTML、Word 或飞书形状后期叠加，保证文字正确且可修改。

### 7.4 图注格式

每张真实截图统一使用：

> **当前状态｜系统完成什么｜这张图证明什么｜Synthetic/Mock 边界**

AI 生成视觉必须标注“概念视觉，不代表生产系统界面”；真实截图必须标注当前分支/提交或“待工程冻结后更新”。

## 8. 页面与排版设计

- 封面使用 Deep Ocean 深色视觉，标题留白区保持简洁；
- 正文使用 Fog 背景、White 卡片和 Ocean Green 标题；
- 每一大节先给一句结论，再给依据；段落控制在 3–5 行；
- 表格只用于评分映射、职责矩阵、状态口径和可比较指标；
- 关键观点使用浅色结论卡，不用大段加粗；
- 每 1–2 页至少出现一个视觉锚点，但不超过 10 组主视觉；
- 真实截图优先采用 2×2 流程矩阵，避免超长整页截图；
- 截图裁除浏览器空白、无关菜单和大面积空行，不裁掉 Synthetic/Mock 标识、状态、规则版本或人工确认信息；
- 所有图表编号连续，图注必须是结论句，而不是复述图片内容。

## 9. 业务价值与 ROI 设计

业务价值分为商户、企业运营、风险治理和平台化四层。所有 30%、80% 等数字保持“试点目标”标签，不表述为现有收益。

正文加入公式：

```text
年度潜在节约价值
= 年案件量 × 单案节省时间 × 单位人力成本
+ 减少改派、遗漏和超期产生的风险损失
```

企业试点需要补齐三个输入：年案件量、当前单案处理时长、单位人力成本。Synthetic 演示只报告可复现的流程指标，例如证据缺口数量、补问次数、规则引用覆盖、人工闸门是否触发和审计事件是否记录。

## 10. 参考资料与主张治理

正文使用 `[1]`、`[2]` 编号引用，文末记录标题、发布机构、版本、URL 和访问日期。优先来源：

- Visa 商户争议指南；
- 经核验的 Mastercard 官方争议资料；
- Worldpay Global Payments Report；
- 经核验的 McKinsey Global Payments Report；
- NIST AI RMF 1.0；
- PCI DSS v4.0.1；
- DeepSeek API Documentation。

行业报告只用于说明支付生态复杂性和运营趋势，不用于证明 OceanPilot 已创造收益。卡组织摘要继续标记 `UNVERIFIED_SUMMARY`，生产使用必须由规则专家按地区、版本、生效日期和收单机构有效版本复核。

## 11. 更新与验收流程

文档改写分两次冻结：

1. **结构冻结：** 完成 7000–8500 字 Markdown、全部图位和“计划接入”口径；
2. **证据冻结：** DeepSeek Agent 提供固定提交、测试、真实运行截图后，更新状态、工程证据、截图和 CI 数量。

每次交付必须：

- 检查标题、目录、评分映射和结语是否一致；
- 扫描“已实现/已验证/计划/试点/路线图”是否混用；
- 扫描所有数字是否有实测、硬约束或试点目标标签；
- 检查图片是否有编号、图注、边界和来源；
- 检查 Markdown 相对路径和外部链接；
- 重新构建 DOCX，并逐页渲染检查裁切、分页、字体、表格和图片；
- 更新飞书正文前，先以本地 Markdown 和 DOCX 为事实源；
- 飞书共享权限或正式提交属于外部动作，另行确认后执行。

## 12. 验收标准

文档设计完成的标准：

- 项目定位始终是全生命周期商户成功智能体；
- 拒付始终被表述为本次标杆链路；
- 四项官方评分维度在前两页可直接找到；
- AI 深度同时展示模型、Agent、工具、确定性规则、降级和人工治理；
- DeepSeek 未验证前不出现“已接入”表述；
- 至少包含 2 张愿景/架构型正式视觉、4 组真实流程截图和 2 张对比/价值图；
- 所有生成视觉都不承担工程完成度证明；
- 所有产品完成度主张都能对应页面、API、测试、提交或路线图状态；
- 文档不存在客户、收益、生产数据或生产接入的虚构表述；
- 最终 DOCX 逐页视觉检查通过，飞书版适合匿名评委快速阅读。
