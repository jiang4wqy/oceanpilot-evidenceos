# OceanPilot V2.1 双端操作指南

目前 V2.1 使用独立验证服务 `http://127.0.0.1:8014`；原 8012 演示服务和原案件暂时保留。完整验收记录见 [验证进度](v21-validation.md)。

## 两个业务端，三方协作

| 参与方 | 入口 | 负责什么 |
|---|---|---|
| 商户 | [商户客户端](http://127.0.0.1:8014/v2/merchant) | 本人确认接受或抗辩，提供事实与材料，查看反馈、结果和资金说明。 |
| OceanPayment | [运营端](http://127.0.0.1:8014/v2/operations) | 运营专员接收事件、跟进商户和上游；风控审核材料和权利；主管终审、核对资金和结案。 |
| OceanPilot | 同一案件页面的共享沟通与 Agent 检查面板 | 读取获授权的消息和材料，检查缺口与期限，检索来源、回答问题、准备待确认提案，并将不确定事项交给负责人。 |

OceanPilot 嵌在两端，没有第三个业务客户端。维护人员另有隔离的演示导演页，用于准备合成交易和管理账号；导演不能替代商户作决定或替代审核人员批准。

## 登录及双端演示

打开 [登录页](http://127.0.0.1:8014/v2/login)，使用本机提供的账号。V2.1 不再通过页面上的角色选择器切换身份。

本机隔离演示已准备 `merchant-a`、`merchant-b`、`operator-a`、`operator-b`、`risk-reviewer`、`supervisor`、`administrator` 和 `director`。随机密码只保存在未跟踪的 `work/v21-qa/accounts.json`，不会写入仓库。

同时展示双方时，请使用不同浏览器或独立浏览器配置文件。普通同一浏览器的多个标签页会共用登录 Cookie；另一个标签页登录会更换该浏览器的会话。风控和主管是独立账号，须分别登录完成审核。

两端必须进入同一案件编号。列表点击案件进入独立案件页；页面上的“返回我的案件”或“返回争议工作队列”返回列表。另一个商户看不到本案，直接输入地址也不能取得权限。

## 从规则资料开始准备演练

运营端案例库保留 Visa、Mastercard 等原始提炼资料。编号最高为 `CB-CASE-074`，实际收录 **62 条**，编号不连续；其中 28 条有演练模板，26 条适用于当前 Visa/Mastercard 工作流。原文示例、规则衍生场景和合成演练各有来源标记，不能都当作真实拒付数据。

1. 在运营端案例库查看条目、来源页码、版本、冲突与未知字段。选中资料不会自动授予抗辩权利或生成真实交易。
2. 演示维护人员用独立 `director` 账号进入 [演示准备页](http://127.0.0.1:8014/v2/director)，明确登记合成交易的商户、交易编号、渠道、卡组织、金额、币种及来源引用。
3. 运营专员登录运营端，点击“接收上游事件”，填写来源事件编号、事件类型、发生时间、接收时间及相同交易事实。先核对再确认接收。
4. 正式拒付且交易匹配才建立案件。预警和查询保留在事件列表；无法关联的事件进入待核对队列。核对合成登记事实后，填写理由重试原事件；重复接收不会重复立案。
5. 引用模板的案件若提示规则或期限待确认，由风控账号核对并确认来源、证据清单、允许的商户决定及当前阶段期限，然后由运营发布商户任务。

发生时间和接收时间来自所填事件，不用点击按钮的当前时间替代。当前 registry 是合成演练事实表，尚未接真实交易系统。

## 同一案件怎样沟通

右侧“本案共享沟通”对本案商户、获授权运营人员及 OceanPilot 可见。发言标明真实参与方；普通发消息和已读回执不会使业务审批版本失效。

填写消息后，勾选“请 OceanPilot 一起回答”再发送，可让 Agent 结合共享往来、材料检查和规则引用回答。例如：“签收材料缺少什么事实？”“这次补证解决了哪个问题？”“下一步由谁确认？”模型不可用时页面显示确定性解释或回退来源，不伪装成模型回答。

运营人员需要内部讨论时，明确选择“内部讨论”。商户无法读取这个范围。旧版各端 AI 私聊保留在历史区，只读且维持原可见范围；不会自动公开到共享线程。

需人处理时展开“请人工接手一个具体问题”，写明原因。事项交给本案实际负责人并保留跟进时间。负责人先接手，再填写处理说明解决；未完成的人工作业会阻止结案。

## 抗辩流程的交接顺序

| 顺序 | 谁操作 | 操作与检查 |
|---|---|---|
| 1 | 运营专员 | 核对案件与已确认规则，发布商户响应任务。 |
| 2 | 商户 | 查看当前可用决定，填写理由，确认接受或抗辩。已确认抗辩后不需要重复作决定。 |
| 3 | 商户 | 在“本案文件与材料”上传对应材料，核对内容检查结果；补齐必需材料后送审。 |
| 4 | 风控审核员 | 检查文件正文和事实，选择通过、退回补材料或建议接受。建议接受交回商户决定，不会自动变成接受。 |
| 5 | 运营专员 | 生成并核对证据包草稿。使用 Agent 提案时可修改字段，系统保留提案原文与实际提交内容。 |
| 6 | 主管 | 独立终审，选择批准、退回材料、退回文书、建议接受或暂缓；批准时完成隐私检查并冻结当前包。 |
| 7 | 运营专员 | 提交已冻结包，检查 Mock 技术送达及业务受理回执。超时或响应丢失时先查询，不能盲目重复提交。 |
| 8 | 运营专员／风控 | 登记上游结果及来源；未知、自定义或待核验结果交风控处理。只有确认终局才进入最终资金核对。 |
| 9 | 运营专员／主管 | 登记合成资金事件；主管依据全部事件核对金额及费用，处理差异。 |
| 10 | 运营专员／主管 | 运营通知商户当前版本结果与资金，主管核对全部关闭条件后关闭；双方页面同步显示。 |

表单底部的业务确认针对当前案件版本。另一人更新材料、规则或结果后，旧确认可能失效；保留输入、刷新当前版本后重新核对。普通聊天不会触发这种业务版本冲突。

## 上传材料的实际范围

当前支持 UTF-8 TXT、JSON、单行交易 CSV，单文件不超过 2 MiB；保存原始文件、hash、版本、上传人及正文位置。暂不支持 PDF/OCR。

结构化合成材料须包含当前案件的 `transaction_id`、`currency`、`amount_minor` 和相应事实。例如收据需要下单时间及商品说明，签收证据需要送达时间及签收确认。各证据类型的准确字段及示例见 [材料内容合同](v21-collaboration.md#真实合成文件)。

“内容检查通过”只表示支持格式和本案关联检查通过，仍须人工判断事实是否成立。空文件、重复文件、与案件金额/币种/交易不符或缺少关键事实的文件不能填满清单。补充新版本或撤回不合适的旧材料后再送审；系统保留旧版本，并使相关旧审核和证据包失效。

所有“登记／补充材料”入口都会打开实际文件上传。新材料不能只填一个网址或对象名称；旧版只有引用的材料仍保留在历史中，需要补充实际文件才能满足当前检查。

遇到“需要人工核验”的未知材料类型，由独立风控账号打开文件正文，选择对应证据，填写支持事实的原文摘录、`line:N` 行号及核验理由，再提交“支持本案事实”或“材料不足”。系统核对原文件、哈希、证据代码和摘录位置；上传人不能核验自己的材料。已明确检查不通过的已知类型须重新补证，不能以人工核验绕过。人工内容核验后仍要经过材料送审及独立终审。

## 常见异常怎样继续

| 情况 | 下一步 |
|---|---|
| 商户未响应 | 风控核验实际剩余权利，按来源依据恢复决定、恢复补证、继续跟进或确认权利处置。不能伪造阶段事件重新开始。 |
| 已抗辩但材料迟交 | 补证逾期单独记录；有效的抗辩决定不会被改成“未响应”。 |
| 商户确认接受 | 运营执行接受处理并读取 Mock 回执；接受不等于自动退款或完成账务。 |
| 上游回复尚非终局 | 区分等待、核验、需行动及进入下一阶段；不直接结案。 |
| 结果 UNKNOWN 或 OTHER | 先核对来源或补充明确映射及依据，再由有权限的人确认。 |
| 已关闭后收到更正 | 主管凭授权和来源事件重开，保留原结案历史，再处理更正与重新通知。 |
| 新资金事件导致旧通知过期 | 重新核对资金并通知当前版本，旧通知不满足关闭条件。 |
| 按钮不可用 | 阅读其禁用原因和当前负责人，完成前置步骤；不能用切换地址或更换请求头绕过。 |

## 金额与当前集成边界

金额输入使用币种的最小单位。USD `12800` 表示 128 美元。部分支持结果分别记录支持金额与责任金额，并与争议金额对应；费用、退款、扣款和返还分别展示，不能把胜诉标签当成已经对账。

指南资料先作为引用来源使用，后续再替换真实数据提供者；已有案件保留创建时来源与规则版本。上游、交易登记和财务目前均为合成/Mock。飞书已进入独立出站与回调联调工作，真实测试群闭环仍待配置和验证；门户可见消息不等于飞书已送达。
