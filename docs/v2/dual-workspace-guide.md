# OceanPilot V2 双端操作指南

适用版本：`oceanpilot-v2`。本文按独立案件页的导航与按钮名称编写；具体案件状态、材料数量与可用操作，以页面当前内容为准。

**先从各自的案件列表进入独立案件页**

- [商户客户端：我的案件](http://127.0.0.1:8012/v2/merchant)
- [OceanPayment 运营端：争议工作队列](http://127.0.0.1:8012/v2/operations)

点击列表中的案件进入专属页面。地址格式分别为 `/v2/merchant/cases/{案件编号}` 和 `/v2/operations/cases/{案件编号}`；可用页面上的“返回我的案件”或“返回争议工作队列”回到列表。OceanPilot 对话位于独立案件页，每次进入另一个案件都会读取该案的对话与推进记录。

例如，若本机仍保留演示案件 `OPV2-afc4f3886a8fea65`，可分别打开它的[商户案件页](http://127.0.0.1:8012/v2/merchant/cases/OPV2-afc4f3886a8fea65?tab=tasks)和[运营案件页](http://127.0.0.1:8012/v2/operations/cases/OPV2-afc4f3886a8fea65?tab=overview)。这只是地址示例，不表示该案件仍处于某个固定版本或处理阶段。

**两个操作端，三个参与角色。** 页面入口只有商户客户端和 OceanPayment 运营端。OceanPilot 是嵌在这两个操作端中的案件智能体，通过各案件的 OceanPilot 面板提供帮助，不是第三个独立客户端。两个操作端共用本机 `8012` 服务端口；“端”在本文中表示面向不同用户的操作界面。

| 参与角色 | 所在操作端／使用位置 | 负责什么 |
| --- | --- | --- |
| 商户 | 商户客户端，角色“商户协作人” | 本人决定接受还是抗辩；提供事实、登记证据、回复反馈 |
| OceanPilot 智能体 | 嵌入商户客户端与运营端的案件面板，无独立入口 | 检查规则与材料、提示期限、生成草稿和待确认提案、回答案件问题、跟进案件变化 |
| OceanPayment | 运营端，按步骤切换运营专员／风控审核员／主管 | 发布任务、人工审核、处理上游、核对资金、通知与结案 |

商户案件页按“案件概况”“我的待办”“抗辩材料”“与运营沟通”“结果与资金”组织。运营案件页按“概览”“商户任务”“证据”“规则与计划”“协作”“审核与提交”“结果与资金”“审计”组织。两端围绕各自职责处理同一案件，页面内容与可执行操作随身份变化。

每次业务操作都要核对弹窗，勾选“我已核对本次操作内容、案件版本及权限，确认执行。”，再点“确认并执行”。下文所说的填写理由，对应表单中的“决策依据 / 说明”。

不需要切换成“Agent（权限演示）”才能使用 OceanPilot。保持本人业务角色，直接在常驻面板中提问或核对提案即可。

当前环境使用合成案件与 Mock 上游。证据功能登记标题、对象引用和说明，不上传或解析文件正文；模拟提交和资金记录也不执行真实提交或资金划转。

**两端怎样自动同步**

可以左右并排打开同一案件的两个页面。商户登记材料、送审或留言后，运营端会自动更新；运营端发布任务、退回补证或登记结果后，商户端也会自动更新，无需每次交接时刷新。案件列表会同步队列变化，案件页会同步进度、材料、协作记录和本端可见的 OceanPilot 活动。后台模型分析可能稍后完成，完成后会自动显示。

自动同步会保留正在输入的提问和操作表单内容。若另一端更新了案件版本，旧确认会失效：保留已填写的信息，关闭旧弹窗，再从最新案件进度发起操作并重新核对。若提问期间案件已变化，页面会保留问题并提示基于最新进展重新发送。

查看顶部同步状态即可判断连接情况。“连接中断 · 自动重连”表示页面正在恢复连接；恢复后会补读期间的变化。右上角“重新同步”用于连接或页面状态异常时主动恢复，不是正常交接步骤。同步恢复前，不要凭旧版本连续提交新操作。

**先使用 GitHub 上提纯的指南案例**

在运营首页点击 [Visa / Mastercard 案例库](http://127.0.0.1:8012/v2/operations/library)。源文件最高编号为 `CB-CASE-074`，去重后实际有 **62 条**：34 条原文示例、13 条规则衍生场景、15 条合成演练。目录提供卡组织、资料性质和文字筛选，详情保留页码、版本、核验状态、冲突与未知字段。

28 条资料附演练模板，其中 26 条适用于当前 Visa／Mastercard 建案流程；Amex 与产品安全模板保留为专项参考。没有模板的原文示例仅用于阅读与 AI 检索，不作为虚构交易自动创建。

1. 例如打开 `CB-CASE-041`，阅读其 Visa 13.1 场景、证据依据与来源冲突，点击“以此模板创建演练案件”。
2. 核对新生成的演练交易编号与事件编号，填写本次演练金额、币种、商户及原因码；例如 `12800` 与 `USD` 表示演练金额 128 美元。这些输入与原文事实分开保存。勾选确认后创建专属案件页。
3. 新案件先等待适用规则确认。切为“OP 风控审核员”，在“规则与计划”核对来源、证据要求、允许的商户权利及明确的演练期限。源模板没有给出交易级截止时间，系统不会自动套用 Golden Demo 的时限。
4. 按实际核对结论填写必需证据代码。041 模板的物流轨迹与签收证明可分别对应 `fulfillment.tracking`、`fulfillment.proof_of_delivery`；是否充分、是否还需补充其他材料由本次规则核对决定。商户、内部、外部截止时间须依次不晚于后一项。
5. 运营专员发布商户任务后，按下文“完整流程”的商户决定、补证、人工审核和上游流程继续。两端均可展开“案例来源”回看原条目；OceanPilot 的新检查和提问会实际检索同卡组织、同原因码的指南案例，并显示引用。

后续接入真实数据时，原案件继续保留创建时的来源和规则快照；真实案件接入与参考资料提供者可以分别替换。现有 A–D Golden Demo 仍可用于快速排练固定合成流程。

**补证交接示例：从缺两项材料继续**

以下假设某演示案件已经选择 Contest，当前清单为 3/5，缺少“收货地址匹配”和“客户沟通记录”。这不是对上述示例案件当前状态的判断；若页面缺口不同，请按实际清单处理。

1. 在商户端打开“抗辩材料”。在“收货地址匹配”这一行点击“补充”。
2. 核对证据类型和标题，填写“证据位置 / 对象引用”。仅供本合成案例排练，可填 `synthetic://guide/address-match-001`；说明填写“合成订单、物流与账单地址匹配示例”。核对弹窗内容，勾选底部确认框，再点“确认并执行”。
3. 同样补充“客户沟通记录”，演练引用可填 `synthetic://guide/customer-comms-001`，说明填写“合成客户沟通与处理经过示例”。
4. 检查该案必需材料已齐备。查看 OceanPilot 的新运行记录和自动解读，或问它：“我已经补齐材料，下一步该由谁处理？”再点击“提交材料给 OceanPayment”。
5. 切到同一案件的运营页，等待状态自动显示为待审核。右上角角色切换为“OP 风控审核员”，进入“审核与提交”，点击“执行风控审核”。之后按下方完整流程第 4 步继续。

如果已选择 Contest，无需再次确认商户决定。登记清单齐备仅表示要求的材料引用已登记，材料内容仍需人工审核。

**完整流程：双端按顺序交接**

从头排练时，先在运营端以“OP 运营专员”点击右上角“演示案例”，选择“A · 正常 Contest”，勾选确认并点击“创建演示案例”。A 会自动建案并发布商户任务；记下新案件编号，在两端列表中进入同一案件的独立页面。不同场景的材料要求不同，以各自清单为准。

| 步骤 | 操作端与角色 | 点击与填写 | 完成后看什么 |
| --- | --- | --- | --- |
| 1. 接案并发布任务 | 运营端／OP 运营专员 | A 演示已自动完成。手动建案时先点“接收上游事件”，再到“商户任务”发布任务；也可核对 OceanPilot 已起草的发布提案后确认。 | 商户收到待响应任务；OceanPilot 显示本案规则、材料清单和下一步。 |
| 2. 明确商户决定 | 商户端／商户协作人 | “我的待办”→“确认我的处理决定”→选择“Contest · 提出抗辩”，填写理由并确认。 | 商户决定变为“提出抗辩”，出现补证任务。 |
| 3. 登记并送审材料 | 商户端／商户协作人 | “抗辩材料”→逐项“补充”，填标题、引用和说明；清单齐备后点“提交材料给 OceanPayment”。 | 案件进入“待 OP 审核”；运营页自动显示新状态，OceanPilot 按新版本更新检查和解读。 |
| 4. 审核材料内容 | 运营端／OP 风控审核员 | “审核与提交”→“执行风控审核”。核对材料，选择“通过 · 准备证据包”并填理由；有问题则选择“退回 · 要求补证”。 | 审核结论与理由留痕。通过后才继续建包；退回后商户补证并重新送审。 |
| 5. 准备证据包 | 运营端／OP 运营专员 | 同页点击“生成证据包草稿”，核对正文。也可从 OceanPilot 已准备的建包提案进入，复核后确认。 | 出现草稿包；展开“查看草稿与来源”，检查材料索引和规则来源。 |
| 6. 独立终审与冻结 | 运营端／OP 主管 | 同页点击“终审并冻结”，选择草稿包，填理由，完成人工敏感信息检查并勾选对应确认；再勾选底部本次操作确认。 | 证据包成为“已冻结”，记录审批人、版本和摘要。风控与最终审批人须不同。 |
| 7. 提交并读回执 | 运营端／OP 运营专员 | 同页点击“确认向上游提交（Mock）”，选择已冻结包，核对并确认。 | 出现提交与回执记录，案件进入“等待上游”。模拟受理不等于已经胜诉或结案。 |
| 8. 登记结果和资金事件 | 运营端／OP 运营专员 | “结果与资金”→“登记上游结果”，填写事件、结果及来源；再“登记资金事件”，填写类型、金额、币种、来源和流水引用。 | 业务结果、是否终局、资金状态分别更新。下方提供假设金额的合成填写示例。 |
| 9. 人工核对资金 | 运营端／OP 主管 | 同页“人工资金核对”，选择结论，填写独立核对得到的预期净影响、理由和凭证引用。 | 正确核对后显示“已核对”；差异未解决时继续处理，不能关闭。 |
| 10. 通知、关闭与查看 | 先运营端／OP 运营专员，再 OP 主管；最后商户端 | 运营专员点“通知商户结果”，核对通知文案；主管再点“确认关闭案件”。商户到“结果与资金”查看。 | 满足关闭条件后，状态为“已关闭”；商户端自动同步结果，运营端“审计”保留整个过程。 |

若手动建案后提示规则待确认，先由“OP 风控审核员”在“规则与计划”点击“查看并确认规则”，明确规则来源、版本、可用权利和期限，之后再发布商户任务。

**结果与资金的合成填写示例**

以下假设一笔 USD 128.00 的合成案件已完成审核、冻结和 Mock 提交，不表示任何现有案件的实时金额或资金状态。若实际演练案件金额不同，或已有资金记录，须结合全部记录重新核对，不能照抄预期净额。

| 操作 | 示例填写 |
| --- | --- |
| 登记上游结果 | 保留表单新生成的事件编号；结果选“胜诉”（`WON`）；按本演练设定勾选“上游明确确认这是终局结果”；来源 `MOCK_UPSTREAM`；理由“合成演示上游确认抗辩成功并返回终局结果”；后续阶段留空。 |
| 登记资金事件 | 保留新事件编号；类型选“返还”（`CREDIT`）；金额填 `12800`；币种 `USD`；来源 `MOCK_UPSTREAM`；引用 `synthetic://guide/credit-001`。 |
| 人工资金核对 | 本演练假设仅有上述一笔返还、没有其他扣款或费用：结论选“已核对”（`RECONCILED`），预期净影响填 `12800`，核对理由“已核对本合成演练账单与返还事件一致”，引用 `synthetic://guide/reconciliation-001`。 |

USD 的金额输入使用美分：`12800` 表示 USD 128.00。资金核对中的“预期净影响”是有符号整数；返还为正，扣款、退款和费用对商户净影响为负。不要把“上游结果是 WON”当作资金已核对。

**每案、每端各有自己的 OceanPilot 对话**

商户端的 AI 历史只属于该案的商户侧；运营端的 AI 历史属于该案的运营侧，不向商户展示。切换案件会切换对话上下文，切换操作端也不会把另一端的 AI 私聊带过来。客观案件进度共同更新，各端的问答、自动解读和待办建议按各自职责展示。

商户端可以直接问：“为什么需要收货地址匹配？”“这些材料分别证明什么？”“帮我起草一条给 OceanPayment 的补证说明。”运营端可以问：“这笔案件目前卡在哪里？”“帮我整理风控审核摘要。”“为什么现在还不能提交或结案？”

| 面板内容 | 使用方式 |
| --- | --- |
| 已完成工具检查 | 展开查看规则、缺证、期限、相似案件和行动准备的实际结果及引用。 |
| 待确认提案 | 看清动作、负责人、案件版本和具体内容；有权限的人核对后确认。缺少引用等信息时先补充表单。 |
| 已备好的文案与摘要 | 查看商户任务、审核摘要或答复草稿；人工复核后再用于相应业务操作。 |
| 对话与自动跟进 | 问具体问题，查看回答上标注的模型与来源。材料登记、撤回、送审等变化会更新工具检查，并在实时模式下触发后台模型解读。 |
| 基于当前版本重新检查 | 需要重新分析或恢复缺失的 Agent 活动时使用；会复用同版工具记录，实时模式可追加模型解读。 |

与 OceanPilot 对话用于本端分析和准备；要让另一端看到说明，请发送案件协作消息。商户在“与运营沟通”中点击“给处理团队留言”，或在“我的待办”中点击“向 OceanPayment 补充说明”；运营人员在“协作”中点击“＋ 协作消息”。这些消息随同一案件在两端共享，AI 私聊不会自动转成协作消息。模型回答本身不会替你完成表单确认，也不会自动向飞书发送消息。

**遇到这些情况怎么处理**

| 情况 | 处理方式 |
| --- | --- |
| 按钮灰色或提示其他负责人 | 看右上角角色及提案负责人。风控审核用“OP 风控审核员”，终审、资金核对和结案用“OP 主管”；商户决定由商户本人确认。 |
| 材料登记了但仍不能送审 | 检查缺失项、证据类型是否选对、记录是否已撤回；当前规则要求的必需材料必须齐备。 |
| 材料清单已齐，但还不能提交上游 | 仍须风控审核通过、生成包、主管终审并冻结。 |
| 提案过期或案件版本已变化 | 自动同步会保留输入并使旧确认失效；关闭旧确认框，从最新进度或新提案重新打开操作并核对。 |
| 顶部提示连接中断，或另一端变化暂未出现 | 等待自动重连；长时间未恢复时点击“重新同步”。确认案件编号和同步状态后再继续，不必在正常交接时手动刷新。 |
| 证据修改后旧审核或证据包失效 | 按当前状态重新送审／审核，再生成和冻结新版本；旧记录保留用于追溯。 |
| 明确显示执行结果不确定 | 使用页面提供的原操作重试入口；不要反复创建新的操作，尤其是结果和资金事件。 |
| 模型暂不可用或显示降级 | 先看工具检查、规则与当前提案；恢复后可重新检查或再提问。降级不会放宽审批条件。 |
| 提交时提示超过外部截止时间 | 先请风控核对规则来源和明确期限，按实际允许的后续流程处理，不能通过模型建议绕过截止校验。 |
| WON 后仍不能结案 | 在“结果与资金”查看关闭条件：必须有明确终局、完成资金核对和必要任务，并已通知商户。 |

**其他演练分支**

- Accept：商户明确接受责任后不继续收集抗辩材料，仍要等待上游终局、核对资金、通知和关闭；选择 Accept 本身不创建退款。
- B · 关键证据缺失：用于演示 Agent 检查缺口、商户补证和运营复核；实际缺失项以新建案例的清单为准。
- C · SLA / 未响应：用于演示期限提醒和人工升级；未回复不会自动变成 Accept。
- D · 财务异常：用于演示已经有终局结果，仍因资金差异无法结案，核对后再通知和关闭。
