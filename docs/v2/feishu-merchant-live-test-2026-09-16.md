## 已定位的问题与修复优先级

### P1：无权限／不存在案件查询静默失败

真实私聊负面测试触发访问层异常，事件路由把错误作为 HTTP 404 返回飞书，没有生成用户可见回复。后续日志出现同路径重复 404；没有用户提示的事实已由客户端和队列交叉确认。

建议：仅对已经验签并验证来源的消息，保留统一、不区分存在性的“无法访问该案件，请从我的案件中选择”回复；持久化消费／去重，避免可预期访问拒绝成为反复投递。不能放宽案件授权，也不能把认证失败当作普通成功。

涉及 `private_cases.py` 的 `query`／消息异常边界及 `dispute_feishu.py` 的事件错误映射。

### P1：自然问法被检索阈值挡住

只读重现：长句能力问题命中 0 份文档；“能帮我做什么”命中产品说明；“在哪里上传材料”命中材料指南。检索使用分词／汉字二元组重叠及 0.35 覆盖阈值，长句中的无关词会稀释相关比例。

建议：意图识别或分句检索，使用已有批准资料回答；补充长句、多问、同义问法回归测试。不能简单降到几乎任意重叠都能回答，更不能拿私人案件补公共知识。

### P1：私聊缺少无模型条件下的意图回答

当前配置未启用私聊模型。`query` 读取案件概况，`focused_card` 在模型为空时直接返回原卡，所以进度、退回、期限、代办问题出现相同正文。

建议：先实现确定性的“问题 → 授权事实 → 商户下一步”模板，无模型也能逐项回答；不适用状态明确说明。期限显示北京时间、剩余时间和当前是否仍需行动。对于代审核、代提交请求，明确说明不可执行及网站人工流程。无需为了改善这些基础交互而把模型接上数据库或业务命令。

### P2：公共业务知识与渠道引导不足

目前只有六份产品／演示指南。签收争议准备思路、经核准的规则解释等尚未构成可用公共知识。需业务负责人提供或批准可公开材料、来源和适用范围；不得擅自发布案件规则快照或宣称合成清单是 VISA 官方统一要求。

群内转交提示可增加“本人案件请到机器人私聊（先绑定）；上传／审核仍在网站”的说明。帮助文案应清楚区分“群内我不查”与“整个机器人都不能查”。

### P2：展示层有外部“相关知识”干扰

测试绑定问题时，飞书客户端另行展示了与本产品无关的“表情包助手／微信 QQ 绑定”相关知识；这不是 OceanPilot 保存的回复卡片或引用。演示时应明确只将 OceanPilot 卡片作为机器人回答证据，避免混淆。未修改第三方知识、群配置或应用设置。
