# V2.1 双端界面与真实账号验收

2026-09-09，使用独立的 8014 服务、隔离 SQLite 与合成交易数据。浏览器为本机 Google Chrome，Playwright 独立上下文分别登录商户、运营、风控、主管和导演账号；未使用角色请求头代替身份。测试账号密码与临时数据库不包含在交付文件中。

## 已通过的业务路径

- 导演登记明确的 synthetic 交易。运营通过标准化上游事件入口接收 `FORMAL_DISPUTE`，随后向商户发布任务。
- 商户选择抗辩，上传五份包含对应交易事实的真实 UTF-8 JSON 文件，内容检查均为 `SUPPORTED`，再提交材料。
- 独立风控人员审核通过，运营生成材料包，独立主管完成最终审核和 PII 确认，运营提交至明确标记的 Mock 上游。
- 上游结果为 `UNKNOWN` 时，风控页面显示核验主动作；风控拒绝无法确认的结果后，案件恢复原来的等待状态。
- 已知结果 `WON`、分流 `WAIT` 保持非终局及原轮次，不自动制造上诉或后续阶段。
- 登记 `WON / FINAL` 后，运营登记合成返还，主管核对净额，运营向商户发布当前结果与资金通知，主管关闭案件。

完整闭环使用案件 `OPV2-fc92e33fge34c3f9c`，操作覆盖真实表单、服务端版本、权限、确认和可用动作。Mock 受理及合成资金记录不代表卡组织受理或真实银行入账。

## 实际文件与独立内容核验

- 所有新增材料入口均打开真实文件上传，清单按钮带入对应代码和标题；不再通过新建外部引用冒充实际文件。
- 缺交易关联字段的文本被判为 `INSUFFICIENT`，不能通过人工核验绕过。商户在界面撤回原文件，再上传包含本案交易编号、币种、金额的文本。
- 未覆盖自动检查合同的类型获得 `NEEDS_MANUAL`。独立风控在文件卡查看真实正文，以原句和 `line:4` 提交核验成功。该判断不替代后续整包审核与最终审核。

## 界面、隔离与恢复

- 商户与运营使用各自首页和案件页；正常页面不提供角色切换、导演或跨端导航。
- 共享消息在两端自动出现，OP 内部讨论不向商户公开；实际文件对应同案的同一对象。
- 文件上传和案件自动更新保留尚未发送的草稿。共享与 OP 内部草稿分别保存。
- 不确定的 OP 内部消息在刷新后恢复原范围、原内容和原命令 ID，可核对重试，不会强迫将内部消息改发共享会话。
- 按后端 `available_actions` 显示负责人、主动作、禁用理由和字段约束；未取得授权或案件读取失败时进入明确结束态。
- 商户结案页仅读取公开业务结果和 `financial_summary`，不使用已移除的运营事件明细拼接虚假时间线。

- 实际断网发送 OP 内部消息后，重连并刷新页面恢复原内部范围；键盘 Enter 使用同一命令 ID 核对发送，最终只出现一条消息。
- 1440px、1024px、390px 页面与聊天入口检查通过，无横向溢出。另以 720 CSS px / 2 倍像素密度检查 200% 等效布局；此项不是原生浏览器缩放快捷键验收。
- 最后一轮上述实际交互没有 JavaScript 页面错误。前端专属回归为 79 项通过。
